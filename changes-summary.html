Pipeline structure
NEW foodseq_reference_pipeline.Rmd
  • Replaces separate trnL-reference.Rmd and 12SV5-reference.Rmd with a single document containing unified setup, shared SLURM jobs, and parallel Part A (trnL) / Part B (12SV5) sections
  • Part A-CD added later (Aug 2026): a third section building a trnL c/d reference alongside g/h, sharing Part A's species list and NCBI pull — see the trnLCD card below
  • SLURM job submission writes scripts with writeLines() and prints the sbatch command for manual execution — avoids PATH errors when system("sbatch") is called from an OOD RStudio session
  • Animal species list read dynamically from human-foods.csv rather than hardcoded in the script
  • Auto-resolve missing taxonomy IDs: loop over accessions with NA taxon IDs and call query_ncbi_accession() to retrieve them from NCBI, covering accessions added after the SQL database was built
  • NCBI API key chunk added; sources all function files; shared extract_taxonomy() helper used by both parts
  • Manual curation edits from Manual renaming.csv integrated into the pipeline at A5 (manual additions) and A7 (omissions and renamings)
  • Closing "Verify before shipping" section added (Aug 2026): runs qc_reference_build.R automatically once Part A, Part A-CD, and Part B all finish, against a new QC_PREVIOUS_SUFFIX config variable — see the QC gate card below
MODIFIED code/functions/query_ncbi.R
  • Sequence-length filter 0:50000[SLEN] added to NCBI search query Root cause of crashes: chromosomal/scaffold assemblies containing the 12S gene were included in results; these can be megabytes each and push the FASTA payload over R's 231−1 byte string limit. The filter excludes them while retaining all genuine amplicons and gene-level sequences. Trade-off found later (Aug 2026): the same cap excludes every complete plastid/mitochondrial genome, which blocks ~41 plant species that have no other public trnL record — see "Remaining gaps" in README.md.
  • Retry logic (fetch_with_retry()) wraps every entrez_fetch() call — retries up to 4 times with a 10 s wait on SSL / network drops instead of aborting the whole query
  • retmax added to entrez_fetch() — caps sequences downloaded per chunk as a secondary size guard
  • Chunk size reduced 50 → 5 species per query to reduce per-fetch payload size
  • 0.5 s pause between chunks to respect NCBI rate limits; progress messages updated to show chunk N of total
  • Key parameters (chunk_size, max_seq_len, retmax_fetch, max_tries, retry_wait) exposed as function arguments for easy tuning
MODIFIED code/functions/find_primer_pair.R
  • Added relationship = "many-to-many" to both inner_join() calls Newer versions of dplyr warn when a many-to-many join is detected without this argument. Finding multiple primer binding sites per genome sequence is expected behaviour; the argument makes this explicit and silences the warnings. No change to results.
NEW code/functions/query_ncbi_accession.R
  • Added to code/functions/; called in the taxonomy lookup steps (A6, B6) to resolve accession numbers that are absent from the local taxonomizr SQL database because they were added to NCBI after the database was built
  • Fixed (Aug 2026): now searches <accession>[ACCN] instead of a free-text entrez_search on the bare accession string The free-text search silently mismatched: a bare-genus string like "Esox" (221k unrelated hits) resolved to whatever NCBI record most recently mentioned the word — live-verified to resolve to a trematode, not the fish genus. This was the second half of the bare-genus accession bug (see the Reference-integrity card below); the fix makes a "not found" case return a safe NA instead of a wrong taxon.
Reference integrity & controls — Aug 2026
NEW data/inputs/controls.csv 92 rows
  • Positive spike-in controls (synthetic trnL/12S ASVs, real-species gecko control) — the food-list-driven rebuild dropped these because they are lab constructs or non-food vertebrates never returned by RefSeq/GenBank queries, so every build was silently missing them Found: 185 synthetic-control 12S ASVs in production data were being reassigned to real fish taxa once the control sequence dropped out of the reference — phantom fish consumption from a QC artifact, not diet.
  • Host-taxon control: Homo sapiens, 89 records — human mtDNA is ~47% of all 12S dietary reads, but human isn't a food, so the food-list-driven pipeline built a reference with no human record at all, sending 400 ASVs / 14.6M reads into food clades (Artiodactyla, Cervidae) once added Traced all 89 records to real public NCBI accessions via BLAST (mostly named human mtDNA haplogroups and Sanger BAC/PAC clone records) — they had been carried forward under synthetic placeholder identifiers with no recorded source.
  • New lineage column distinguishes synthetic constructs (label repeated across all ranks) from real-species controls (true taxonomic lineage) — consumed by new pipeline chunks A10 (trnL) and B9 (12S), inserted between dedup and save
  • QC gate hard-fails if a control is missing — see qc_reference_build.R below
MODIFIED foodseq_reference_pipeline.Rmd — off-target & accession fixes
  • Off-target phylum filter (chunks A6b / B6b): removes cross-kingdom records that reached the reference despite passing primer/PCR filtering Found 21 12S records with bacterial/viral/synthetic lineages on sequences byte-identical to real food fish/bird amplicons (e.g. a record labelled Pseudomonas rhodesiae was actually Dicentrarchus labrax, European seabass). Cross-kingdom decoys collapse DADA2's bootstrap classifier at every rank, producing unexplained "lost assignment" ASVs. trnL allowlist is Streptophyta + Cyanobacteriota (keeps edible cyanobacteria like spirulina); 12S allowlist is Chordata-only, an explicit decision after production data showed only 2 ASVs / 15 reads ever hit an invertebrate phylum.
  • Bare-genus RefSeq accession bug fixed (chunks A2/B2): RefSeq-sourced records now keep "<accession> <Genus species>" instead of being renamed to species-only, which had put a bare genus in the accession field of every RefSeq record A bare genus fed into the old free-text accession lookup (see query_ncbi_accession.R above) and could resolve to the wrong organism entirely — 260 RefSeq-sourced records were affected, several with cross-genus mislabels.
New marker
NEW Part A-CD — trnL c/d reference 4,522 records
  • A third marker alongside trnL g/h and 12SV5, extracting the trnL c/d intron region instead of the g/h P6 loop — useful where g/h degrades but c/d survives (e.g. some processed/degraded DNA contexts)
  • Alignment-augmented extraction, not primer matching: primer-based find_primer_pair() only recovers c/d sites for ~55–58% of taxa the g/h reference already covers, because c/d deposits are frequently primer-trimmed in GenBank. Three tiers instead — plastome introns via primer sites (also serve as an alignment panel), a GenBank primer route, and a GenBank alignment-rescue route (local alignment against family-matched plastome introns) — recover an estimated ~95%+ of g/h-covered taxa
  • CD9 sanity check: warns if fewer than 80% of extracted introns carry the trnL-g anchor sequence, since g anneals inside the intron and its absence signals a bad extraction
  • No trnLCD-specific positive control exists yet (the synthetic construct has no c/d priming sites); the controls chunk will auto-pick-up a future marker=trnLCD row in controls.csv once the wet lab settles on one
Quality control
NEW code/qc_reference_build.R
  • Automated gate run against every built reference: header/rank completeness, no meaningful rank ≥99% NA, required controls present, staple food genera present, clade consistency (no bacterial/viral/parasite phyla), every sequence carries a real accession, and record-count drift vs. the previous build flagged if it exceeds ±25%
  • Takes [REPO_DIR] [CURRENT_SUFFIX] [PREVIOUS_SUFFIX] so any two dated builds can be diffed, plus an optional 4th argument restricting the check to a marker subset — needed by Extend reference.Rmd, which only ever touches one marker per run
  • Hard-fails (exit 1) on missing controls or broken rank structure; soft-warns on record-count drift and dropped species, so a WARN-only run still needs a human read before shipping
  • Wired into both pipelines that build a reference (Aug 2026): a new closing "Verify before shipping" section in foodseq_reference_pipeline.Rmd runs it automatically once Part A, Part A-CD, and Part B finish — mirroring the same pattern Extend reference.Rmd already used. Neither pipeline can now finish a build without the gate running; running it is no longer a separate step someone has to remember
New workflows
NEW code/Extend reference.Rmd
  • Adds a handful of newly-available species to an existing reference without a full cluster rebuild — runs on a laptop in minutes, querying NCBI directly for both sequence (query_ncbi()) and taxonomy (fetch_lineage_ncbi(), new SQL-free e-utils lookup), so neither the cluster nor the ~70 GB accessionTaxa.sql is required
  • Never overwrites the reference it extends — always writes a new, separately-suffixed output pair (e.g. _Aug2026 → _Aug2026_ext)
  • Same 50 kb length cap as the full pipeline, so it inherits the same complete-genome blind spot; not usable for trnLCD, whose alignment-based extraction needs the full plastome panel rather than a single per-species query
  • Intended to run after Coverage recheck.Rmd below — that notebook's CANDIDATES_*.csv outputs are already in the scientific_name-column format this one's ADDITIONS parameter expects
NEW code/Coverage recheck.Rmd
  • Consolidates nine standalone scripts (bash + R, now in archive/code/coverage-recheck/) that did the same NCBI-existence-check job across separate files, several with paths hardcoded to one person's machine — into one portable notebook using here()-relative paths throughout
  • Part 1 (routine): checks whether species already on human-foods.csv but missing from the current build now have marker data at NCBI — computed fresh from the built reference each run, plus a new name-resolution step (species → current NCBI-accepted name) that catches synonym drift, e.g. Allium porrum → Allium ampeloprasum That resolution step is new: its absence in the original July 2026 run meant 40% of that run's plant candidates were already-covered species listed under an outdated name.
  • Part 2 (occasional, toggle-able): audits a curated list of ~199 globally significant foods against human-foods.csv for species missing from the target list entirely, not just missing sequence
  • Checkpointed/resumable NCBI queries, matching the retry conventions already used by query_ncbi.R / query_ncbi_accession.R — Part 1 alone is a multi-hour job against ~1,500 species unauthenticated
