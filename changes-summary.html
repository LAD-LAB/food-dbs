Corrections to release 2026.08
MODIFIED Extend reference.Rmd & qc_reference_build.R — orientation fix defect in the deposited release
  • The defect: the full pipeline stores every amplicon forward-primer-first (steps A9 / B8), but Extend reference.Rmd had no such step, so any record taken from a minus-strand GenBank entry went into the reference reverse-complemented. The deposited 2026.08 12SV5 file contains 52 such records, all from the September recovery. The October recoveries raised the count to 355 12SV5 and 12 trnL records before it was caught DADA2's assignTaxonomy() matches the forward strand only by default, so reads from those species could not be assigned to them. Noticed because the 12SV5 maximum amplicon length had jumped to 437 bp while preparing the new Zenodo upload.
  • The fix: Extend now orients every amplicon and rejects lengths outside the reference's range (two 437 bp Pseudophycis breviuscula records were dropped); the QC gate has a new check that fails on any reverse-first record; every affected record in 2026.10 was reverse-complemented and 20 exact duplicates this exposed were removed. coverage-recheck/ORIENTATION_fix_Oct2026.csv lists each record and whether it was in the deposited release
  • Also corrected: the 2026.08 README said the trnL g/h and 12SV5 sequences exclude the priming sites. They include them; only trnL c/d is primer-trimmed.
MODIFIED foodseq_reference_pipeline.Rmd & trnLCD — two mislabelled records 4,522 → 4,520
  • The records: JX390727.1, labelled Murraya koenigii, is a peanut (Arachis hypogaea) sequence — 99–100% identical to peanut c/d records and 74.5% to other Murraya; GU595140.1, labelled Secale cereale, is a rice (Oryza) sequence — 98.7–99.8% identical to rice and 92.2% to other Secale. Both were in the deposited 2026.08 trnLCD and are removed from 2026.10; each species keeps its other records, so no coverage is lost Both had already been omitted from trnL g/h through Manual renaming.csv, but those omit rows are keyed to the g/h amplicon sequence and can never match a c/d record. A third g/h omission, KF550171.1 (Allium schoenoprasum), was checked and is normal in c/d (301 bp, 99.7% identical to other Allium), so it is kept.
  • The fix in the pipeline: step CD7 now omits the two accessions explicitly (trnLCD_omit), with the evidence in a comment, so a rebuild cannot bring them back
MODIFIED database files — line endings CRLF → LF
  • The 2026.08 trnL g/h and 12SV5 FASTA files use Windows (CRLF) line endings, because the laptop Extend workflow wrote them; the cluster-built files, including trnL c/d, use LF. Every file in 2026.10 uses LF Strict FASTA parsers can read a stray carriage return as part of the sequence or header. Found when the generator that rebuilds the QIIME2 files failed to reproduce the released trnLCD file byte for byte: Windows R's writeXStringSet() writes CRLF.
  • Extend now strips the carriage returns it would write, and the QC gate has a new line-ending check (10) that fails on any CR. Run against the released 2026.08 12SV5 files it fails, as it should

NEW Recoveries and additions after the cluster build
  • 202 animals restored. A new comparison against the 2025 reference found 202 food-list animal species that it held and 2026.08 lacked (cod, pollock and tuna among them). Each has a valid V5 amplicon at NCBI. The cause of the loss is known for two of the first ten (the 500-result fetch cap per batch of five species) and not established for the rest
  • 58 more animals (yak, llama, guanaco among them) were found by checking every food species missing from the build against NCBI — one row per species in coverage-recheck/GAP_check_Oct2026.csv

  • Dropped: two out-of-range Pseudophycis breviuscula amplicons and 20 exact duplicates exposed by the orientation fix
Food list & synonyms
MODIFIED data/inputs/human-foods.csv 234 build_name entries
  • New build_name column: the name(s) the reference uses for an entry when NCBI files its sequences under a different taxon — a rename (Pisum sativum → Lathyrus oleraceus), a spelling variant, or an infraspecific name NCBI does not recognise. scientific_name is never changed by it, so coverage denominators are unchanged. 165 plants and 69 animals; read by the QC gate Without it, every species NCBI files under another name looked missing even when covered, and comparisons with the 2025 reference reported them as losses.
  • Name review of 149 names NCBI Taxonomy did not recognise (checked against GBIF and NCBI): 15 misspellings corrected in place with the original kept in notes, 31 names mapped through build_name, and 10 doubtful GBIF synonymies (e.g. Melilotus macrorhizus, Polyprion yanezi) left unapplied. Five mapped rows duplicate a correctly spelled row already on the list — flagged, not deleted. One row per name in coverage-recheck/NAMES_resolution_Oct2026.csv
NEW known-absent-species.csv & reference-additions-*.csv
  • known-absent-species.csv: food-list species deliberately absent from a build, with the reason (for example an amplicon that contains ambiguity codes, which the build drops). Read by the coverage ratchet; the gate prints a prune notice when a listed species becomes present. 6 rows
  • reference-additions-*.csv: the species list used for each Extend run (cod/pollock/tuna, legacy-losses-191, Sander, gap-check-58, name review for 12S and trnL, plastome), each with a notes column recording why — a provenance trail for what was added after the cluster build
Quality control
MODIFIED code/qc_reference_build.R
  • Coverage ratchet (check 6b): pins trnL and 12S to a fixed legacy baseline (the 2025 reference) instead of "the previous build" — every food-list species it held must still be present, directly or through build_name, unless known-absent-species.csv documents why. An undocumented loss is a FAIL The earlier gate compared each build only with its predecessor, so ~200 species vanished unnoticed: each build was compared with one that had already lost them. The ratchet found 202 animal losses and none for plants.
  • Orientation (check 9): FAILs on any record that starts with the reverse primer — the same rule and mismatch tolerance as pipeline steps A9 / B8
  • Finds an archived previous build: if the previous-suffix file is not beside the current one, it looks in archive/<suffix>/ (e.g. _Aug2026 → archive/aug2026/), so archiving a release does not turn the record-count and species-drop checks into a skipped WARN
  • Line endings (check 10): FAILs on any carriage return in a database FASTA, so a Windows-written CRLF file cannot ship again
Workflows
NEW code/functions/query_ncbi_plastome.R plastome path for trnL
  • Finds complete chloroplast genomes by organism and title (chloroplast[TITL] OR plastid[TITL], 50,001–400,000 bp) and fetches them one record per request, returning the same shape as query_ncbi() so find_primer_pair() and the rest of Extend work unchanged A plant whose only trnL sequence sits in a GenBank plastome was invisible to every earlier path: the 50 kb cap removes the genome, and plastome titles never name the gene, so the marker search misses ~96% of them.
  • Run over the 344 plants still missing: 73 had a clean amplicon (70–117 bp, the same range as the existing records), added as 83 sequences covering 76 taxa; 6 algae have a plastome without the trnL g/h sites; 257 have no plastome either. 15 of the 73 are filed by NCBI under another name and mapped with build_name (e.g. Polianthes tuberosa is Agave amica)
  • Bug fixed during the first run: paste0() renders 400000 as 4e+05, which NCBI read as a malformed length range and answered with zero hits for every species. Now sprintf("%d").
MODIFIED code/Extend reference.Rmd & Coverage recheck.Rmd
  • SOURCE <- "plastome" (trnL only) searches complete chloroplast genomes instead of marker records under 50 kb, closing the complete-genome blind spot for plants. Still not usable for trnLCD
  • Every amplicon is now stored forward-primer-first, and amplicons far outside the reference's length range are rejected (see the first card)
  • Default suffixes moved to _v2026.10 in both notebooks (Extend: _v2026.10 → _v2026.10_ext)
  • Output FASTAs are written with LF line endings even on Windows (the carriage returns writeXStringSet() adds are stripped)
MODIFIED data/inputs/Manual renaming.csv 30 → 23 rows
  • Removed the 5 rename rows and 2 exact-duplicate add rows. The file now holds only what the pipeline reads: 20 add rows (mostly whole-genome records beyond the 50 kb query cap, merged in at step A5) and 3 omit rows (step A7) The rename rows were never read: the pipeline hard-codes the same five Brassica oleracea variety renamings in A7 and CD7. The hard-coded version is kept, and a comment in A7 now records its source (BP, Jan 2023: identified to variety level in the cited reference).
